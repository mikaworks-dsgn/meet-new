# meet-new

まだ知らない「好き」と出会う、セレンディピティ(ちょうどいい意外さ)を実現する、分析・提案の試作プロジェクト。

accessible-device-guide-ai の「ニーズカード」機能の、次の段階として位置づける。入力された興味・体験をもとに、意外性のある別の興味・体験を提案する仕組みを検証する。

## 解決したいこと
自分が今まで触れたことのないものには、気づく機会が少ない。
「近すぎる」おすすめではなく、「少し離れているけれど、関係はある」という、ちょうどいい意外さを届けたい。

## 仕組みの考え方
1. 対象を、2つの、グループに、分ける
   - コンテンツ(70件):身近な、趣味・流行・体験(メイン8件+候補62件)
   - 名著(123件):文学・思想・歴史の、本
2. それぞれの、特徴的な、要素(軸)を、取り出す
3. 軸を、埋め込み表現(ベクトル)に、変換する
4. 次の、2種類の、比較を、行う
   - コンテンツどうしの、比較:「近すぎず、遠すぎない、別の、コンテンツ」を、見つける(例:ちいかわ→たまごっち)
   - コンテンツ→名著の、比較:コンテンツの、軸から、関連する、名著を、見つける(例:ちいかわの"不条理"→関連する、文学作品)
5. 「共通する、軸がある」+「独自の、軸もある」組み合わせを、「ちょうどいい、意外さ」と、判定する
6. その、組み合わせが、面白い、理由を、LLMが、説明する

## 対象コンテンツ

### メイン(8件、文章を集めて、しっかり分析する)
ちいかわ、伊能忠敬界隈、マーラータン、ドバイチョコ餅、たまごっち、めじるしチャーム、スクイーズ、シール交換

### 候補(62件、LLMで、手早く軸を生成する)
イマーシブ体験、リアル脱出ゲーム、横浜花博、スコーン、ミルクティー、サンリオ、MBTI、VRフィットネス、ブロックブラスト、M!LK、料理研究家、推し活、setlog、読書、グランピング、コンセプトカフェ、御朱印巡り、ボードゲーム、ピクニック、工場見学、デジタル日記、NISA、カービー、散歩、パン屋巡り、サウナ、古民家ステイ、アフタヌーンティー、ソロキャンプ、聖地巡礼、ホカンス、陶芸体験、ブックホテル、ワーケーション、せいろ蒸し、グリークヨーグルト、生ドーナツ、デカドリンク、おにぎり、バッグチャーム、平成レトロ、パーソナルカラー、ASMR、ブラインドボックス、ぬい活、AI画像、デジタルデトックス、note、ジャーナリング、ガチャガチャ、マーダーミステリー、リスキリング、ポッドキャスト、ボルダリング、かばんの中身紹介、朝活、コト消費、ZINE、応援上映、哲学カフェ、建築探訪、ポケモン

### 名著(123件)
日本語・海外の、文学・思想・歴史などの、名著。それぞれ、10個の、軸を、LLM(Claude)の、知識から、直接、挙げてもらった。文章は、収集していない。データは、data/books_axes.json に、保存。

## 技術構成
- 形態素解析:Janome(ローカル環境に導入済み)
- 埋め込み表現:sentence-transformers(使用モデル:sonoisa/sentence-bert-base-ja-mean-tokens-v2、768次元)
  - ローカルPCのメモリ不足(RAM約4GB)でモデルを読み込めなかったため、Google Colab(無料のクラウド環境)上で実行する方式に変更した
- LLM(提案理由の説明に使用予定):Colab上で、Qwen2.5(1.5B・3B)を試したが、精度・速度の面で、軸の抽出には向かなかった。当初はOllamaでローカル実行する予定だったが、ローカルのメモリ不足のため、Colabに切り替えて、試した
  - 候補・名著、およびメインの追加分の軸は、対話型のAI(Claude)の知識から、直接、挙げる方式に変更した。そのため、Colab上のLLM(Qwen2.5)は、現時点では、提案理由の説明にのみ、使う予定
- 文章収集:公式サイト・関連記事など、無料で読める範囲に限定する

## 進め方(段階)
1. メインの8コンテンツについて、公式サイト・記事などから文章を集める(完了)
2. 集めた文章をもとに、特徴的な要素(軸)を3〜4個、挙げる。その後、候補・名著と軸の数を揃えるため、残りの軸を、LLMの知識から追加で挙げ、10個にする(完了)
3. 候補の62コンテンツは、文章収集をせず、LLMに直接、軸を生成してもらう(完了、data/candidate_axes.jsonに保存済み)
4. 名著123作品は、文章収集をせず、LLM(Claude)の知識から直接、軸を10個ずつ生成してもらう(完了、data/books_axes.jsonに保存済み)
5. すべての軸の名前(ラベル)を、埋め込み表現に変換する(完了、1930個の軸を約1分でベクトル化。data/embeddings.npyとdata/axis_index.jsonに保存)
6. コンテンツ(70件)どうしの軸を、総当たりで比較し、意味が近い軸を見つける(完了)
   具体的には、700個の各軸について、他のコンテンツの軸との、コサイン類似度を計算し、類似度0.5以上の軸の中から、上位3件までを、おすすめとして保存した(data/axis_recommendations.json)。あわせて、コンテンツ単位での比較結果も、参考として保存した(data/good_pairs.json、類似度0.55以上の、一致する軸があり、かつ、独自の軸(相手のどの軸とも類似度0.15以下の軸)がある、という条件で判定)
7. コンテンツ(70件)の軸と、名著(123件)の軸も、同じように、総当たりで比較する
8. 「一致する軸」と「独自の軸」の組み合わせから、コンテンツどうしの意外性のあるペアと、コンテンツから名著へのペアを、それぞれ選び出す
9. LLMが、提案理由を説明する

軸の数について:メイン8コンテンツ・候補62コンテンツ・名著123作品、すべて10個ずつに揃えた。ただし、メインの軸は、最初の3〜4個は集めた文章にもとづき、残りはLLMの知識にもとづいて追加したもので、作り方が混ざっている。

## 注意点
- 作品名・コンテンツ名は、分析用のラベルとして扱う。画像・ロゴ・公式文章の転載はしない
- 実在の人物名は、個人を特定する形では扱わず、カテゴリとして抽象化する(例:「料理研究家」)
- ローカルPCのGPU VRAM、および、RAM(メインメモリ)が、それぞれ約4GB程度と少ないため、埋め込み表現とLLMの実行は、Google Colab(無料のクラウド環境)上で行う
