# meet-new

**実際に動く画面はこちら:https://skgwzmalbhhyqfjdhqfo6k.streamlit.app/**

まだ知らない「好き」と出会う、セレンディピティ(ちょうどいい意外さ)を実現する分析・提案の試作プロジェクト。

accessible-device-guide-ai の「ニーズカード」機能の次の段階として位置づける。入力された興味・体験をもとに、意外性のある別の興味・体験を提案する仕組みを検証する。

## 解決したいこと
自分が今まで触れたことのないものには、気づく機会が少ない。
「近すぎる」おすすめではなく、「少し離れているけれど関係はある」というちょうどいい意外さを届けたい。

## 仕組みの考え方
1. 対象を2つのグループに分ける
   - コンテンツ(70件):身近な趣味・流行・体験(メイン8件+候補62件)
   - 名著(123件):文学・思想・歴史の本
2. それぞれの特徴的な要素(軸)を取り出す
3. 軸を埋め込み表現(ベクトル)に変換する
4. 次の2種類の比較を行う
   - コンテンツどうしの比較:「近すぎず、遠すぎない別のコンテンツ」を見つける(例:たまごっち→ちいかわ。「世話をする喜び」と「愛らしさ」が共通し、たまごっちには「成長の変化」という独自の軸がある)
   - コンテンツ→名著の比較:コンテンツの軸から関連する名著を見つける(例:ちいかわの「切なさ」→森鷗外『舞姫』の「愛を選べない切なさ」。ちいかわには「日常」という独自の軸がある)
5. 「共通する軸がある」+「独自の軸もある」組み合わせを、「ちょうどいい意外さ」と判定する
6. その組み合わせが面白い理由を説明する文章を表示する

## 対象コンテンツ

### メイン(8件、文章を集めてしっかり分析する)
ちいかわ、伊能忠敬界隈、マーラータン、ドバイチョコ餅、たまごっち、めじるしチャーム、スクイーズ、シール交換

### 候補(62件、LLMで手早く軸を生成する)
イマーシブ体験、リアル脱出ゲーム、横浜花博、スコーン、ミルクティー、サンリオ、MBTI、VRフィットネス、ブロックブラスト、M!LK、料理研究家、推し活、setlog、読書、グランピング、コンセプトカフェ、御朱印巡り、ボードゲーム、ピクニック、工場見学、デジタル日記、NISA、カービー、散歩、パン屋巡り、サウナ、古民家ステイ、アフタヌーンティー、ソロキャンプ、聖地巡礼、ホカンス、陶芸体験、ブックホテル、ワーケーション、せいろ蒸し、グリークヨーグルト、生ドーナツ、デカドリンク、おにぎり、バッグチャーム、平成レトロ、パーソナルカラー、ASMR、ブラインドボックス、ぬい活、AI画像、デジタルデトックス、note、ジャーナリング、ガチャガチャ、マーダーミステリー、リスキリング、ポッドキャスト、ボルダリング、かばんの中身紹介、朝活、コト消費、ZINE、応援上映、哲学カフェ、建築探訪、ポケモン

### 名著(123件)
日本語・海外の文学・思想・歴史などの名著。それぞれ10個の軸を、LLM(Claude)の知識から直接挙げてもらった。文章は収集していない。データは data/books_axes.json に保存。

## 技術構成
- 形態素解析:Janome(ローカル環境に導入済み)
- 埋め込み表現:sentence-transformers(使用モデル:sonoisa/sentence-bert-base-ja-mean-tokens-v2、768次元)
  - ローカルPCのメモリ不足(RAM約4GB)でモデルを読み込めなかったため、Google Colab(無料のクラウド環境)上で実行する方式に変更した
- LLM(試したが、現在は不使用):Colab上でQwen2.5(1.5B・3B)を試したが、精度・速度の面で軸の抽出には向かなかった。当初はOllamaでローカル実行する予定だったが、ローカルのメモリ不足のため、Colabに切り替えて試した
  - 提案理由の説明もテンプレート方式に変更したため、現時点ではLLMは使っていない
- 文章収集:公式サイト・関連記事など、無料で読める範囲に限定する
- 画面:Streamlit

## 進め方(段階)
1. メインの8コンテンツについて、公式サイト・記事などから文章を集める(完了)
2. 集めた文章をもとに、特徴的な要素(軸)を3〜4個挙げる。その後、候補・名著と軸の数を揃えるため、残りの軸をLLMの知識から追加で挙げ、10個にする(完了)
3. 候補の62コンテンツは、文章収集をせず、LLMに直接軸を生成してもらう(完了、data/candidate_axes.jsonに保存済み)
4. 名著123作品は、文章収集をせず、LLM(Claude)の知識から直接軸を10個ずつ生成してもらう(完了、data/books_axes.jsonに保存済み)
5. すべての軸の名前(ラベル)を埋め込み表現に変換する(完了、1930個の軸を約1分でベクトル化。data/embeddings.npyとdata/axis_index.jsonに保存)
6. コンテンツ(70件)どうしの軸を総当たりで比較し、意味が近い軸を見つける(完了)
   700個の各軸について、他のコンテンツの軸とのコサイン類似度を計算し、類似度0.5以上の軸があり、かつ元のコンテンツのいずれか1つの軸が相手のすべての軸と比べて類似度0.20以下である(独自の軸がある)という両方の条件を満たすものを保存した(data/axis_recommendations.json)。また、「非日常」と「日常」のように片方にだけ否定の接頭語(非・不・無・反)が付いている場合に加えて、「不条理」と「非日常の発見」のように両方に否定の接頭語が付いていても、接頭語を除いた残りの言葉が違う場合も除外するフィルターを加えた(data/axis_recommendations.json と data/book_recommendations.json は scripts/rebuild_recs.py で作成した)
7. コンテンツ(70件)の軸と名著(123件)の軸も、同じように総当たりで比較する(完了)
   同じ条件で、コンテンツの軸から名著へのおすすめを保存した(data/book_recommendations.json)
8. 選んだ軸から「ちょうどいい意外さ」のあるおすすめを見られる画面を作る(完了、app.py)
9. 提案理由を説明する文章を表示する(完了、app.py)
   テンプレートに実際の軸の名前を当てはめる方式で作成した(4パターンを用意し、組み合わせに応じて選ぶ)。当初の構想ではLLMに理由を説明させる予定だったが、以前Qwen2.5を試した際の精度・速度の課題を踏まえ、安定して動くことを優先してテンプレート方式に変更した

軸の数について:メイン8コンテンツ・候補62コンテンツ・名著123作品、すべて10個ずつに揃えた。ただし、メインの軸は、最初の3〜4個は集めた文章にもとづき、残りはLLMの知識にもとづいて追加したもので、作り方が混ざっている。

## 注意点
- 作品名・コンテンツ名は、分析用のラベルとして扱う。画像・ロゴ・公式文章の転載はしない
- 実在の人物名は、個人を特定する形では扱わず、カテゴリとして抽象化する(例:「料理研究家」)
- ローカルPCのGPU VRAMおよびRAM(メインメモリ)が、それぞれ約4GB程度と少ないため、埋め込み表現とLLMの実行はGoogle Colab(無料のクラウド環境)上で行う

## 今後の展望
accessible-device-guide-ai の「ニーズカード」(今の気分を読み取る機能)と組み合わせ、
気分に合ったちょうどいい意外さのある体験を提案する一連の流れを目指す。

## 使い方
1. Streamlitをインストールする(初回のみ)
   `venv\Scripts\python.exe -m pip install streamlit`
2. 画面を起動する
   `venv\Scripts\python.exe -m streamlit run app.py`
3. ブラウザで http://localhost:8501 を開く
4. 好きなコンテンツを選び、気になる軸のボタンを押すと、コンテンツと名著のおすすめが共通する軸・独自の軸とあわせて表示される
