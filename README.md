# meet-new

まだ知らない「好き」と出会う、セレンディピティ(ちょうどいい意外さ)を実現する、分析・提案の試作プロジェクト。

accessible-device-guide-ai の「ニーズカード」機能の、次の段階として位置づける。入力された興味・体験をもとに、意外性のある別の興味・体験を提案する仕組みを検証する。

## 解決したいこと
自分が今まで触れたことのないものには、気づく機会が少ない。
「近すぎる」おすすめではなく、「少し離れているけれど、関係はある」という、ちょうどいい意外さを届けたい。

## 仕組みの考え方
1. コンテンツ(趣味・体験)ごとに、固有の特徴的な要素(軸)を抽出する
2. 軸を、埋め込み表現(ベクトル)に変換する
3. 異なるコンテンツ同士で、軸と軸を比較し、意味的に近い軸を見つける(軸のマッチング)
4. 「一致する軸がある」+「対応する軸がない(独自の)軸もある」という組み合わせを、ちょうどいい意外さとして判定する
5. LLMが、なぜその組み合わせが面白いか、理由を言葉で説明する

## 対象コンテンツ

### メイン(文章を集めて、しっかり分析する)
ちいかわ、伊能忠敬界隈、マーラータン、ドバイチョコ餅、たまごっち、めじるしチャーム、スクイーズ、シール交換

### 候補(LLMで、手早く軸を生成する)
イマーシブ体験、リアル脱出ゲーム、横浜花博、スコーン、ミルクティー、サンリオ、MBTI、VRフィットネス、ブロックブラスト、M!LK、料理研究家、推し活、setlog、読書、グランピング、コンセプトカフェ、御朱印巡り、ボードゲーム、ピクニック、工場見学、デジタル日記、NISA、カービー、散歩、パン屋巡り

## 技術構成
- 形態素解析:Janome(ローカル環境に導入済み)
- 埋め込み表現:sentence-transformers(日本語対応モデル、無料)
  - ローカルPCのメモリ不足(RAM約4GB)でモデルを読み込めなかったため、Google Colab(無料のクラウド環境)上で実行する方式に変更した
- LLM(軸の抽出・理由説明):Colab上で、軽量なLLMを試す予定(モデルは追って決定)
  - 当初はQwen2.5をOllamaでローカル実行する予定だったが、ローカルのメモリ不足のため、まだ試せていない
- 文章収集:公式サイト・関連記事など、無料で読める範囲に限定する

## 進め方(段階)
1. メインの8コンテンツについて、公式サイト・記事などから文章を集める
2. 集めた文章をもとに、LLMに「特徴的な要素(軸)を3〜5個挙げて」と頼む(RAGの形)
3. 候補の25コンテンツは、文章収集をせず、LLMに直接、軸を生成してもらう
4. 軸の名前(ラベル)を、埋め込み表現に変換する
5. 全コンテンツの軸同士を、総当たりで比較し、意味が近い軸を見つける
6. 「一致する軸」と「独自の軸」の組み合わせから、意外性のあるペアを選び出す
7. LLMが、提案理由を説明する

## 注意点
- 作品名・コンテンツ名は、分析用のラベルとして扱う。画像・ロゴ・公式文章の転載はしない
- 実在の人物名は、個人を特定する形では扱わず、カテゴリとして抽象化する(例:「料理研究家」)
- ローカルPCのGPU VRAM、および、RAM(メインメモリ)が、それぞれ約4GB程度と少ないため、埋め込み表現とLLMの実行は、Google Colab(無料のクラウド環境)上で行う
